## 一、产品定位

**在 Raycast 里管理所有项目的 .env 和全局 shell 配置——本地、免费、键盘优先。**

- 形态:Raycast 扩展(TS + React)
- 策略:先自用再上架,按上架标准写代码(数据结构、错误处理不糊弄)
- 更新:上架后由 Raycast Store 自动推送(npm run publish,版本号 package.json,说明写 CHANGELOG.md)

## 二、核心架构(最关键的三刀)

### 1. 真相源 = .env 文件本身(不是扩展数据库)

- 扩展**不存环境数据**。项目轨就是直接编辑项目目录下的 .env 文件
- 私有存储只存:项目注册表、UI 状态、快照历史、"上次读取的文件指纹"
- **冲突检测**(Q2c+Q6c 的落地):打开项目时读文件并记指纹 → 保存时再摸一次文件:
  - 指纹一致 → 直接写入
  - 指纹变了(外部改过)→ 弹窗:载入新版 / 强行覆盖
- 不做自动双向同步、不做后台文件监听(v1)

### 2. 双轨文件模型

| 轨 | 真相源 | 生效方式 |
|---|---|---|
| 项目轨 | 项目目录下 `.env.<环境名>` | 前端框架/Docker 原生读取;可选 direnv 转发(v2) |
| shell 轨 | 扩展拥有的 `~/.env-butler/shell.sh` | `.zshrc` 一行 source;该文件用户不该手改 |

- 项目轨:扩展改的就是项目那个 .env 文件,没有第二份
- shell 轨:两个文件(.zshrc 只有一行 source,内容在 shell.sh);alias 不做独立概念,就是片段

### 3. 扩展私有存储 = 自建目录,全透明

```
~/.env-butler/
  ├── registry.json         ← 项目注册表(项目名、路径、敏感标记)
  ├── shell.sh              ← shell 轨生成文件
  └── snapshots/
      └── <项目名>/
          └── 2026-09-01-183430.env.development
```

- 不用 Raycast localStorage 存业务数据(叙事一致性:本地、透明、用户拥有;换机 = 拷目录)

## 四、明确不做(v1 砍掉)

仪表盘/图表 · 主题切换 · 账号/会员 · 自建更新机制 · 全局激活项目概念 · 自动双向同步 · direnv 完整集成(v2) · 加密/密钥管理(v2,与 dotenvx 互补) · PATH 通过 launchctl 注入宣传(系统限制,不可承诺)

### 项目轨的"分组"(2026-09-06 补记)

`功能整理.md` 的 v1 清单里原本有"分组:创建 + 关联变量 + 筛选",到本文档时静默消失了,
既没实现也没记理由。现在补上结论:**不做,因为架构上没有它的位置。**

- 原版有分组,是因为它**把数据存在自己的数据库里**,分组只是它自己数据的一个字段
- 我们的真相源是 `.env` 文件本身,而 **dotenv 格式里根本没有"组"这个概念**——只有 `KEY=VALUE`、注释、空行

于是只剩两条路,都不通:

| 路线 | 做法 | 为什么不做 |
|---|---|---|
| 用注释行当分组标记 | 识别 `# --- Database ---` 之后的连续变量为一组 | 等于**拿扩展的约定去要求别人的项目代码**。`.env` 谁都能改,写法五花八门,识别规则宽了误判、严了认不出 |
| 分组信息存 registry.json | 按 key 名记 group | **违背 §二 的架构基石**。分组是关于文件内容的结构信息,存进 registry 就开了口子,以后"变量描述""变量顺序"都会想往里塞,registry 慢慢变成第二个真相源;而且换机、同事 clone 都会丢 |

顺带记下"不编辑 .env 也能改项目环境变量"的完整方案空间(2026-09-06 调研),
以后有人再提这个方向时不用重来一遍:

| 注入层 | 代表 | 覆盖范围 | 代价 |
|---|---|---|---|
| shell 全局层 | 原版的"全局激活项目"、手改 `.zshrc` | 所有新开终端 | **污染全局**;无法并行多项目;已开终端不同步;**Dock 启动的 GUI 应用读不到**(它们继承的是 launchd 环境,不是 shell 的) |
| shell 目录层 | direnv | 该目录下的终端 | 还是要在项目里放文件(`.envrc`),只是换了个名字;要装 direnv |
| 进程层 | `dotenvx run`、`mise exec` | 精确到一条命令 | 必须改启动方式 |
| 系统层 | EnvPane、`launchctl setenv` | 连 GUI 应用都吃得到 | 污染最严重;SIP 之后限制多;重启不保留;Apple 不鼓励 |
| 链接层 | 项目里的 `.env` 做成软链 | 等同 .env | 软链会进 git,团队协作直接坏 |
| IDE 层 | 编辑器插件 | 仅该 IDE 内 | 一个 IDE 一套 |

**结论:"不编辑 .env"的代价永远是把状态搬到别处**,而别处只有三种下场——污染范围更大、
要求用户改变启动习惯、或者还是得在项目里放个文件。原版选了污染最大的那条,
所以才有 `功能整理.md` §五 记的那三个致命缺陷。
现在"直编 .env"是唯一一条不需要用户改变任何习惯、又天然支持并行的路。
真要补覆盖范围,未来该做的是**进程层**(提供 run 包装或与 dotenvx 联动),而不是回到注入。

## 五、差异化卖点(商店页面三行)

1. **Secrets masked by default** — 敏感值默认打码,一键揭示/复制
2. **Snapshot & rollback, free forever** — 每次修改前自动快照,.env 不进 git 也有历史
3. **One-click .env.example** — 从任意环境生成团队模板

## 六、核心分层与跨平台复用（2026-09-01 补）

**动机**：不把功能绑死在 Raycast。若弃用 Raycast，丢的只是 UI 壳，核心逻辑与数据零损失；核心也可复用到将来的个人工作台 / CLI。

### 分层原则

```
raycast/（壳,只接界面） → 依赖 → core/（纯逻辑,零平台依赖）
```

- **core**：纯 TypeScript + Node,不出现任何 `@raycast/api` / `@tauri-apps/*` 引用。全部是"领域操作"(解析 .env、生成 .sh、快照命名、冲突指纹、脱敏识别)。
- **raycast(壳)**：只 import core,用 List/Form/Detail 把核心操作映射成界面,**不写业务逻辑**。

### 朴素分层(现在只用到的两条,不提前做接口)

Node-only 阶段(现消费方全是 Node:Raycast/CLI/未来的 Electron)**不做接口抽象**,只有两条纪律:

1. **数据变换写成纯函数**:输入字符串 → 输出结构/字符串,不碰 fs。如 `parseEnv(input): EnvEntry[]`、`generateSh(entries): string`。测试直接喂字符串断言。
2. **一次性副作用靠传参注入**:如快照命名的时间戳 `snapshotName(t: Date)`,默认传 `new Date()`,测试传假时间。fs / child_process 在 Node-only 下直接用,不抽象。

### 端口预留(仅当出现第二个非 Node 消费方时才落地)

| 端口 | 各平台实现 |
|---|---|
| EnvStore(读写 .env) | Node:`node:fs` / Tauri:`@tauri-apps/plugin-fs` / Web:无(砍掉形态的原因) |
| Exec(执行 shell) | Raycast:`useExec` / Node:`child_process` |
| Time(时间戳) | 各平台 Date |
| Secrets(可选密钥存储) | Raycast 加密库 / 工作台自己的存储 |

> 跨语言说明:接口契约能被重写成任何语言(20 行),真正的资产是 core 里的纯算法;跨语言时用 WASM/FFI 或重写,接口形状作文档约定保留。

### core 纪律(用 ESLint 强制)

- `no-restricted-imports`:禁止 `/Volumes/coding/project/env-butler/core` 目录 import `@raycast/api`、`@tauri-apps/*`
- core 只暴露领域操作,不暴露 `showToast()`、`getPreferenceValues()` 等平台 API
- core 每个 src 文件保持**纯函数 + 显式副作用参数**,便于 vitest 直接断言(见 §六"朴素分层")

### 包命名

### 核心约束：raycast 必须独立于 pnpm(2026-09-01 修订,推翻此前 workspace 方案)

**喂给商店的是整个源码项目**(PR 进 raycast/extensions 仓库),商店 CI 用 **npm** 跑 `npm install`,官方要求提交 `package-lock.json` 以锁定确切版本(保证"本地装的版本 == 商店装的版本")。**商店只认 npm 的 lockfile,不认 pnpm/yarn 的;也不认 workspace: 协议。** 因此正解是：

- ✅ raycast/ 自成一体:自己的 package.json + package-lock.json,本地就用 npm 操作这个包,pnpm 不碰它(锁文件由 npm 生成,交商店才"安装一致")
- ✅ core 作为**已发布的真实版本依赖**进 raycast:`"@env-butler/core": "^0.0.1"`(本地开发期用 file:,提交前换版本号)
- ✅ core 自己用 pnpm 没问题(core 是发往 npm 的对象)
- ❌ 反例(pnpm workspace 一把梭)行不通:商店 CI 的 npm 不认识 workspace 协议;根目录 pnpm-lock.yaml 商店也不读,版本不受控

### 开发与发布循环(2026-09-02 实测修正)

```
日常开发:  raycast 目录内 npm run dev(热更新);core 单独用 pnpm test
联动 core: 本地 file: 依赖是符号链接 → core 源码改动不会自动生效,
           必须先在 core 目录跑 pnpm build(tsc 出 dist),raycast 才读到新逻辑
发布:      npm publish core → 把 raycast 的依赖从 file: 改成 ^版本号 + npm install 刷新 lockfile
           → npm run publish 提商店
```

- **单人推荐**:日常在 core 改完就 `pnpm build`,raycast 立即经符号链接读到;提交商店前写一个 5 行脚本把 `file:../env-butler/core` 换回 `^版本号` 并 `npm install`(只有一处替换,可靠);同时保持 core 小步发版(0.x 随便升)做双保险

## 八、遗留待定(v1 开发中再定)

> 状态:2026-09-06 复盘,三条里两条已定夺,只剩一条待定。

### 仍未定夺

- 敏感词识别误报/漏报的实际调整(现状:纯关键词匹配 + 手动覆盖,尚未用真实 .env 批量校准)。
  这一条要靠实际使用积累样本,不适合凭空定

### 已定夺(2026-09-06)

- **"复制某环境为 .env"的防呆:先做覆盖确认,不做 .gitignore 检查。**
  目标 `.env` 已存在时弹确认框(覆盖前照常打快照,内容捞得回来)。
  `.gitignore` 检查暂不做——要解析通配符与否定规则 `!` 才能判准,成本高;
  而"按一下就换掉一整个文件"是所有人都会撞上的,优先级更高。
- **shell 轨片段顺序:做上移/下移,不做拖拽排序。**
  顺序会真实影响功能(`export PATH="$JAVA_HOME/bin:$PATH"` 必须排在定义 `JAVA_HOME` 之后,
  排错了不报错、只会让命令莫名找不到),core `moveShellSnippet` + 界面 ⌘⇧↑/⌘⇧↓。
  同时修正了本节原先"预览可见"的错误前提——列表按类型分组显示,
  和文件里的真实先后并不一致,因此补了「查看生成的 shell.sh」动作与详情面板里的"排列顺序"。
- **shell 轨片段的「类型」字段**(环境变量 / alias / 脚本片段):曾讨论是否砍掉,**决定保留**,
  并补了不阻塞保存的类型温和提示(`matchesDeclaredType`)

## 九、2026-09-06 补强(数据安全与两轨对齐)

这一批不是新功能,是把"会伤到用户"的地方补上。按性质分四组:

### 1. 数据安全

| 问题 | 结论 |
|---|---|
| `registry.json` / `shell.json` 损坏时**静默返回空配置** | 改为抛错。storage 把原文件改名成 `.corrupted-<时间戳>` 挪走,界面明确报错并可在访达中定位。原先的链条是:用户看到空列表 → 以为要重建 → 一保存就把还留着原始数据的坏文件覆盖掉 |
| 写文件不是原子的 | 统一走 `writeFileAtomic`(临时文件 + rename)。两个坑:目标是符号链接要先 `realpath`;要保留原文件权限(用户可能 chmod 600 过 `.env`),`shell.sh` 显式传 `0o755` |
| Shell 轨完全没有历史 | 新增 `config-history/`,`shell.json` 与 `registry.json` 每次写入前存一份;配 `diffShellSnippets` 与恢复界面。Shell 轨对历史的需求其实**比项目轨更强**:`.env` 至少可能在 git 里有副本,片段只存在一处 |
| 改 `~/.zshrc` 前不备份 | 动手前复制到 `backups/`。rc 文件每开一个终端都会执行,写坏了用户很难联想到是这个扩展 |
| 同一秒内连续保存快照会**撞名覆盖** | 时间戳只精确到秒,补 `-2` / `-3` 序号(实测复现过) |
| `version` 字段有但解析时不读 | 补上真实的版本判断:版本高于当前明确报错(用户降级扩展时,当旧版处理会把新字段写没);缺 version 的早期文件按 v1 放行。迁移接缝先留着 |

### 2. 两轨对齐(§九 曾列出的"不该有差异")

- **快照/回滚**:Shell 轨补齐(见上)
- **敏感值打码**:Shell 轨补齐。片段是自由文本,`maskShellContent` 逐行找 `KEY=值` 形态再判断;
  另有手动的「这段里有敏感信息」勾选兜底。**打码只影响显示**,`shell.sh` 里必须是明文
- **全局搜索覆盖**:补上 Shell 轨。命令叫 Search Env Vars,搜不到 Shell 轨的变量会被当成 bug
- **外部修改冲突检测**:**决定不做**。`shell.json` / `shell.sh` 只有这个扩展会动,
  且已有历史可回滚,再加一层裁决弹窗性价比不高

### 3. 泄漏面

- 所有可能含密钥的复制动作加 `concealed`,不进 Raycast 剪贴板历史。
  一个主打"敏感值默认打码"的工具,不该界面上藏好、一按复制就进了另一个可搜索的明文库

### 4. 工程基建

- **`tsconfig` 修好了**。交接说明里写的"tsc 报一堆 @types/node 假错误"不是假错误,是配置问题:
  `moduleResolution` 缺省成 `node10` 不认识 `node:` 前缀,且 TypeScript 6 下 `types` 必须显式写。
  修好后暴露出 3 个真错误(已修),并新增 `npm run typecheck`
- 项目 id 与路径解耦:原先是路径的 base64,目录一改名 id 就变,绑在 id 上的设置全部失效

## 十、2026-09-06 界面验收后的修正

第一次把 §九 那批改动放进真实 Raycast 界面里走查,发现的问题按性质分三组。

### 1. 真 bug

| 问题 | 根因与结论 |
|---|---|
| 一进项目就自己弹出「新建环境文件」表单 | 下拉框首次渲染时文件列表还是空的,那一刻下拉里**只剩哨兵项**;而 Raycast 的下拉在挂载时会把当前选中项回调一次,于是哨兵被当成用户的选择。改成"文件列表探测出来之前不渲染下拉框",并在 `onChange` 里再挡一道。**入口方案本身没问题,问题是没防住"未加载完就触发"** |
| `exprot PASSWORD=xxx` 一路放行 | `zsh -n` 查的是语法,而这一行语法完全合法(shell 理解成"带临时环境变量执行 exprot 这条命令")。新增 `lintShellSnippet` 猜错别字,用**受限 Damerau-Levenshtein**(相邻字符互换算一步)——最典型的 `exprot` / `exoprt` 正好是字母调位,普通编辑距离会算成 2,跟"随便打错两个字母"混在一起。定位是提醒不是错误:`env FOO=bar cmd` 也是合法写法,所以确认后仍可保存,只是把默认按钮设成"回去改" |
| 已禁用的变量**不打码** | 列表里禁用区直接显示 `kv.value` 明文。禁用不等于不敏感,被注释掉的 `PASSWORD` 仍然是密码。已与启用区统一 |
| `backupShellRc` 同一秒备份会覆盖 | 和快照那次是同一类错误,但这次出现在 `.zshrc` 备份上。"手动存一份 → 立刻恢复"正好落在同一秒,结果安全备份把用户刚存的原件盖掉,恢复出来的反而是坏内容。**这是假 HOME 端到端验证抓到的,读代码没看出来** |

### 2. 差异区重做(原先三个毛病叠在同一块 UI 上)

- **方向歧义**:标题写"与当前版本的差异",但算的是 `快照 → 当前`,"新增 KEY"指的是当前多了一项。
  读的人会自然读成反的。现在标题一律写成 `A → B`,条目描述的永远是"从 A 到 B 发生了什么"
- **看不出"这一版改了什么"**:只有"相对当前"一个基准,历史列表最自然的读法(逐版看演进)反而缺席。
  补上「上一版 → 此版本」,与「此版本 → 当前版本」并列
- **禁用状态不进差异**:`diffEnvVariables` 只比 key 和 value,"值没变但整行被注释掉"会被判成 unchanged 而消失。
  已纳入 `disabled` 比较

两个历史页共用 `views/diffFormat.ts`,不再各写一套。

### 3. 一致性与补齐

- **详情面板统一去掉红点**:`- ` 会被渲染成主题色圆点,红色在界面里通常意味着错误。
  Shell 片段详情早就改了,快照和配置历史两个页面漏掉
- **列表图标统一**:两个历史页都给时间戳配 `Icon.Clock`(时间戳是纯数字串,有图标扫读快很多)
- **清理旧记录**:`SnapshotCleanupForm` 泛化,Shell 配置历史也能清理
- **复制**:项目轨补「复制整行 KEY=VALUE」(粘到别的 `.env` 或终端里最常用的其实是整行);
  Shell 配置历史补复制动作(此前一个都没有)。第一轮只补了项目轨的已启用区,
  全局搜索结果项和已禁用区漏了(2026-09-06 界面验收追问发现,commit `3c58c98`)——
  已补齐,且两轨的"禁用"含义不同,复制规则也不同:项目轨的禁用是整行被注释,
  照原样带上 `#`;Shell 轨的禁用是整个片段不生成,行本身没被注释,不加前缀
- **全局搜索跳转落点**:此前跳过去只带 project,搜到 `.env.prod` 里的变量、跳过去看到的却是 `.env` 的列表顶端。
  现在带上环境文件名与变量名(Shell 轨带片段 id),直接停在搜到的那一项上;placeholder 也改成如实描述搜索范围

### 4. 单个片段的历史:只读,不做单点回滚

Shell 配置历史支持按片段筛选(`focusSnippet`),但**回滚仍然是整份配置回滚**。
理由:单独把一个片段回滚回去,很容易凑出一个从来没存在过的组合——
A 回到旧值、B 还是新值,而两者本来是配套的。看历史是零风险的,回滚不是。

页面标题只提一个片段、动作却会连带改动别的片段,这本身容易让人误判影响范围
(2026-09-06 界面验收追问发现,commit `3c58c98`)。已在确认框里补上说明:
先算一遍这一版跟当前配置的差异,把除本片段外还会被连带改动的片段逐个点名;
如果这一版跟当前没有其他差异,也明说"这次只会影响它"。动作名同时从
「恢复到这份配置」改成「恢复整份配置到这一版」,避免读成"只恢复这个片段"。

### 5. `.zshrc` 备份从隐形变成可见

`backups/` 里的副本一直都在(接入 / 移除 Shell 集成时各存一份),但界面上从没提过。
**用户不知道存在的保险等于没有保险**,所以:

- 新增备份列表页,可查看内容(默认打码)、恢复、删除、在访达中定位
- 支持手动备份,可选默认目录或自选目录——改 shell 配置前想留个后路,不该逼人开终端敲 `cp`
- 接入 / 移除 Shell 集成的提示里带上备份路径

三者的分工写清楚,免得再混淆:`backups/` 是**你自己那份 `.zshrc` 的原样副本**;
`config-history/` 是**扩展自己的 `shell.json`(片段)**;`snapshots/` 是**项目的 `.env`**。

手动备份与自动备份有一处故意的不同:**手动备份失败要抛错**。
自动备份只是顺手上的保险,失败了不该拖累主流程;而手动备份本身就是用户此刻唯一想做的事,
悄悄失败等于给了一份不存在的安心。

### 6. 导入 / 导出配置:暂不做

`功能整理.md` 里列过,但现状只有「在访达中显示数据目录」(换机 = 拷目录)。
真要做,绕不开一件事:**导出文件里会有明文密钥**,落到下载目录或聊天软件里就是事故。
要么导出时强制排除变量值(只导结构),要么给非常显眼的警告。v1 先不做,后续再议。

## 十一、项目轨「方案」(2026-09-09 定稿并实现,待界面验收)

### 1. 起因:两个发现

**发现一:项目轨真正站得住的价值只有两条**——`.env` 的历史/回滚(它被 gitignore,
没有任何别的备份手段)和跨项目搜索。"多环境切换"目前只是把几个文件并排放着,谈不上能力。

**发现二:`.env.development` / `.env.production` 这种按后缀自动加载,不是通用规则。**
逐个查过:只有 Vite / Next.js / CRA 这类前端构建工具会自动识别;Python(`python-dotenv`)、
Ruby(`dotenv-rails`)、Go(`godotenv`)、Rust(`dotenvy`)默认都只认字面 `.env`,切换要代码里显式指定;
Java/Spring 用 Profile + `application-{profile}.properties`、.NET 用 `appsettings.{Environment}.json`,
根本不走 `.env`;Docker 不传 `--env-file` 也只认 `.env`;Kubernetes 用 ConfigMap/Secret,
没有"文件"这个概念。**`.env` 是"前端 + 脚本语言"的偏好,不是行业标准。**

所以项目轨不该围着"框架会不会认后缀"设计——那是项目自己的事,插件猜不准也不该猜。
用户真正要的是:**几套常用的值之间快速切换,不用每次重新输入**。

### 2. 定位:两套机制并存,不是替换

| | 项目目录里的 `.env*` 文件 | 方案 |
|---|---|---|
| 存在哪 | 项目目录,随项目走 | 插件私有存储 `~/.env-butler/presets.json` |
| 服务谁 | 框架会自动读取后缀文件的场景(Vite/Next/CRA) | 只有 `.env` 真正生效、其它文件只是摆设的场景 |
| 现有功能 | 全部保留:下拉切换、直接编辑、参考其它文件填充空文件 | 新增 |

### 3. 命名:「方案」(英文 Profile)

淘汰过四个词,每个的问题都不一样:

- 不叫「预设」:听起来像插件内置的,其实全是用户自己存的
- 不叫「变量」:界面里"变量"已经指单条 `KEY=VALUE`,再拿来指"一整份内容"会撞车
- 不叫「快照」:快照是写入前自动生成的历史点,方案是用户主动命名保存的,性质不同
- 不叫「方案」(实现过一版又改掉):方案/备份/快照都是"把过去某一刻留下来",**朝向是往回看的**;
  而这个东西是"几套平行的配置,选一套用",是往前看的。而且项目里已有「快照」扮演备份角色,再放一个「方案」在旁边会糊成一团
- 不叫「环境」:刻意去掉"开发/生产"的语义包袱,方案可以是"客户老王""免费额度账号"这类跟部署阶段无关的东西

「方案」的好处:"套用方案 A""切换到方案 B"读起来顺,天然带"从几个里选一个"的意思,没有备份味也没有内置味。
代码里的标识符仍叫 `Preset`(改名只改用户看得到的文案,不动 API)。

### 4. 存在插件里,不写进项目目录(推翻了 §二"真相源=文件"的一次误用)

一度按 §二 的原则反对过"存插件",后来被四条理由说服,按分量排:

1. **命名会跟团队文件冲突。** 团队已有 `.env.develop`(提交进 git),用户自己也想叫个"develop"的方案——
   两者抢同一个文件名,是"方案可以随便起名"这个目标本身逼出来的结构性矛盾,不是小概率巧合
2. 不该要求个人习惯去改团队共享的 `.gitignore`
3. 不往项目目录里堆一堆跟项目无关的文件
4. **这不违背 §二。** §二 反对的是"扩展数据库给 `.env` 的内容做二次解读"(§四 否掉"分组存 registry"
   正是这个理由)。方案不解释、不代表 `.env` 现在是什么,只是"一份候选内容",跟 `.env.example` 的定位同类。
   `.env` 该是什么,永远只取决于它自己写着什么

代价是换机/重装插件会丢方案——但这不是新增的风险类别,`registry.json`、`snapshots/`、
`config-history/`、`backups/` 现在全是同样的"本地文件、换机 = 拷目录"。

顺带纠正一个自己之前说错的话:"存插件会让密钥多一处存放"不成立。
不管方案放哪,都是"一份存起来的 + 一份正在生效的 `.env`",两份一直都在,只是前者换了地方。

### 5. 数据结构

```typescript
interface Preset {
  id: string;
  projectId: string;      // 归属项目,不跨项目共享
  name: string;
  note?: string;           // 这份方案是干嘛的
  group?: string;          // 自由文本标签,不是独立实体
  content: string;         // 原始 .env 文本,保留注释/空行/引号
  createdAt: string;
  updatedAt: string;
}

interface PresetsFile {
  version: number;
  presets: Preset[];
  /** "projectId:文件名" → 上一次套用的方案,用来判断内容是否漂移 */
  appliedState: Record<string, { presetId: string; appliedAt: string }>;
}
```

- 写入前照 `shell.json` 的先例存进 `config-history/`;显示默认打码;复制走 `concealed`
- **`registry.json` 不碰。** 它存的是项目元数据(id / 路径 / 上次打开时间 / 自定义敏感词**名单**),
  从来不存变量的值;方案带真实密钥,两者敏感等级不同,不该混在一个文件里,也不该再往 registry 里塞东西
- `appliedState` 也放在 `presets.json` 里,同样是为了不让 registry 膨胀

### 6. 分组:一个字段,不是一张表

分组做成 `Preset.group?: string`,不做独立实体。用数据库的话说是反范式化:
没有 `Group` 表、没有外键、没有"删组时孤儿方案怎么办"。
没人用某个组名,那个组就自然不存在。以后真要升级成独立实体,也只是加东西不用改结构。

**填写交互**(Raycast 表单没有"既能选又能打字"的 combobox,只能拆成两个控件):
`Form.Dropdown` 列出本项目已有的分组供选,加一个 `Form.TextField`"或新建一个分组";
文本框填了就以它为准。这样填的时候看得到已有分组,不会瞎打字造出一堆同义分组。

### 7. 界面动作

- **套用方案**:任意环境文件(含空文件)的操作面板加 Submenu,列出本项目所有方案;
  内容跟当前文件完全一致的打「● 当前生效」——**看内容,不看上次点了哪个**:用户在意的是"现在跑的是哪一套值";
  内容相同的方案有几份就标几份。**目标文件非空时,先进差异页,差异页的主动作才是真正的套用**——
  `confirmAlert` 只有两个按钮,放不下"先看差异",用户得退出确认框去看再回来;索性让差异页本身当确认框,
  确认时看到的是完整差异而不是三个数字。文件为空时直接套,没有东西会被覆盖。
  写入走 `writeEnvFileWithSnapshot`。原先单独的「查看方案差异」子菜单随之删掉(跟套用进的是同一页)
- **新建方案有三条路**,对应三种起点:
  - 存为新方案:内容来自当前文件,只读预览且打码;顺手记成"已套用"(文件此刻就等于它)
  - 新建空白方案:名字 / 备注 / 分组 + 明文编辑框从零写。这里能给明文是因为没有现成密钥要藏
  - 复制一份(管理页里):沿用原件内容,只改名字/备注/分组;要改值走「编辑内容」。同类方案多半只差两三个值,这条最省事
- **管理方案**:独立列表页,按 `group` 分 `List.Section`(组名字母序,未分组固定放最后);
  每项可改名/改备注/改分组、**编辑内容**(复用 `EditShellSnippetForm` 的多行编辑模式)、查看历史、删除、看差异
- **差异对比页**:**复用** `diffEnvVariables` + `views/diffFormat.ts` 那套"A → B"两栏展示,
  喂"方案内容"和"当前文件内容"即可,连打码规则都是现成的。两个入口:套用(差异页即确认步骤,文件页和管理页都从这走)、漂移提示
- **漂移提示**:用 `appliedState` 记住"这个文件上次套用的是哪份方案",每次打开拿现在的内容跟那份方案的
  **当前**内容比对,不一致就在列表顶部提示,附三个动作:「查看差异」「把改动更新进方案」「忽略这次提示」。
  "更新进方案"是画界面时补的:发现两边不一样之后,用户最常见的下一步要么看、要么存回去,只给"看"少一步

### 7 之二. 第一次界面走查后的修正(2026-09-10)

- **动词统一成「套用」**:子菜单原叫"应用方案",管理页里叫"套用到 .env",同一件事两个叫法。现在一律"套用"
- **图标**:套用原用 `Icon.Download`(看着像下载),改 `Icon.Replace`(整份替换,名副其实);差异原用 `Icon.ArrowRight`,改 `Icon.Layers`
- **子菜单标题后面的"..."是 Raycast 自动加的**(表示还有下一级),文案里没有,也不该去掉
- **分组下拉框里的「(不分组)」必须存在**:Raycast 的下拉选了就清不掉,没有这一项就没法表达"不要分组"。
  但一个分组都还没有时,整个下拉框不出现——只剩一个"(不分组)"选项的下拉框没有意义
- **分组要"够得着"**(2026-09-10 走查:"分组看起来没任何作用"):此前分组只当区块标题用,
  而且一个分组都没有时列表还顶着"未分组"标题——只有一个区块还带标题,纯属噪音。现在:
  没有任何分组时不显示区块标题(管理页与套用子菜单都是);管理页搜索匹配组名(`keywords`);
  管理页搜索栏加分组筛选下拉(全部 / 各组 / 未分组),同样只在有分组时出现。
  分组仍只是标签,它的价值随方案数量增长,现阶段只保证该出现的地方都能用上
- **分组可以整体改名 / 解散**(同日走查:"改不了组名,就算能改也传不到所有方案"):这是"分组只是一个字段"的直接后果——
  组名散落在每份方案上,逐份改容易漏,漏一份就分裂成两个组。`renamePresetGroup(file, projectId, from, to)`
  一次改完本项目该组所有方案、一次写入一条历史;`to` 为空即解散(方案保留、只摘掉标签)。
  动作挂在组里任意一份方案上(Raycast 的区块标题挂不了动作)。新名字撞上本项目已有分组 = 合并,先确认。
  **只动本项目**:别的项目里同名的组只是碰巧同名。仍然不做分组实体、分组备注、分组排序
- **环境文件可以整份编辑**(`RawContentForm`,同时给方案内容编辑复用):空文件一个个建变量太慢;
  明文编辑,走 `saveLines` 所以快照与外部修改检测照常生效
- **单份方案的变更历史**(`focusPreset`):筛选出动过它的版本,**恢复只恢复这一份**(`restorePreset`,
  还在就原位覆盖,删了就按原 id 加回来),其他方案不动。
  一度照搬 Shell 片段历史的"恢复整份"——那条理由是片段之间有依赖(`PATH` 引用 `JAVA_HOME`),
  单独回滚会凑出不存在的组合;方案彼此独立、每份都是完整的 `.env` 内容,这个前提不成立,
  整份恢复只是徒增副作用
- **方案历史按项目看**(`restoreProjectPresets`):`presets.json` 是全局一份、只有一条历史线,
  但用户永远是从某个项目进来的。列表只留本项目有变动的版本,详情只列本项目的方案,
  恢复只把本项目的方案换回那一版、其他项目不动。"误删了一批"靠这一层救。
  **已知限制**:移除了项目登记之后,它的方案跟着清掉,没有入口再找回(项目都不在了,进不去它的历史);
  真需要再加

### 8. 这次明确不做

- **跨项目共享方案**——每个项目一份;不同项目变量名不一样,共享容易"套上了但对不上"
- **按需合并式套用**(只覆盖方案里提到的 key)——先整份替换,有真实用例再加,合并语义会引出"没提到的 key 怎么办""冲突听谁的"
- **分组做成独立实体**——见 §6
- **数量软上限提示**——真多起来直接复用已泛化的 `SnapshotCleanupForm`

## 十二、两轨为什么不必长得一样(2026-09-11)

方案落地后,自然会问:Shell 轨要不要也对齐成"有方案"?反过来,项目轨为什么不像 Shell 轨那样用"片段"?
两个问题的答案是同一个:**两轨的文件归属不同、需求形状不同,原语就该不同。** §九.2 说的"对齐"
一直是"同一个用户需求两边都得有"(快照、打码、搜索),不是把结构做成一个模样。

### 1. 前提纠正:项目轨的真相仍是 `.env`

方案存在插件里,但它只是"候选内容",不解释、不代表 `.env` 现在是什么(§十一.4 第 4 条)。
项目轨现在是"真相(`.env`,在项目里)+ 候选库(方案,在插件里)+ 历史(快照)";
Shell 轨从第一天起就是"真相(`shell.json`,在插件里)→ 生成 `shell.sh`"。两边结构本来就不一样。

### 2. Shell 轨不做方案

- `.env` 里的方案解决的是**同一组 key、几套互斥的值**(客户 A / 客户 B 的三个值是一整套,只能有一套生效),所以整份换
- Shell 配置是**累积**的:alias、PATH、工具变量彼此独立,绝大多数时候想要"全都在"。
  真正互斥的只有少数几个(代理开关、`JAVA_HOME` 8/17、`AWS_PROFILE`、公司/个人 git 身份),
  而这些**已经由"一个片段一个开关"解决了**:互斥的两个值就是两个片段,开一个关一个
- 硬做的两种形状都不站得住:整份互换会为了切一个 `JAVA_HOME` 复制几十条无关 alias,之后必然漂移;
  "场景 = 一组开关状态"形状对,但收益只在"≥3 个开关总是一起动且切得频繁"时出现——热插拔本身已经小众,场景是小众上再乘小众。
  **记入待定,等真实痛点**

### 3. 项目轨不用片段

- **文件归谁**:Shell 轨的片段能成立,是因为 `shell.sh` 由插件生成、没人在插件背后改它(所以那边连外部修改检测都不做)。
  项目轨若用片段,就得让插件生成 `.env`,`.env` 从真相变成派生物——同事、`vercel env pull`、vim 的每一次改动
  都要"反解析回片段"或被覆盖,正是 §二 第一刀否掉的东西。要在别人也读的 `.env` 里标记"这块属于片段 A、现在关着",
  只能靠注释约定,§四 已否:拿扩展的约定去要求别人的项目文件
- **需求形状**:Shell 少一个 alias 什么也不发生,`.env` 少一个 `DB_URL` 程序启动就崩;
  Shell 两个片段同 key 后者覆盖前者、通常无害,`.env` 同 key 两行则 `dotenv` 取第一个、别的库取最后一个,静默出错。
  方案是**原子**的——套用后文件是一个已知的完整状态,差异、"当前生效"、漂移检测都建立在这上面;片段的和没人保证完整
- 方案模式的代价是公共部分复制 N 份、改公共 key 会漂。真到那一步,解法也不是片段,而是"方案 = 基底 + 覆盖层",即 §十一.8 的"按需合并式套用",现在不做

### 4. 顺带补上的 Shell 轨缺口:重复设置提示

"一个片段一个开关"欠的一笔:两个已启用片段都设了 `JAVA_HOME`,插件什么都不说,shell 里静默以生成顺序靠后者为准。
`findShellConflicts` 找出已启用片段间同名变量 / 同名 alias;列表打橙色标签「重复 · JAVA_HOME」,
详情面板写清跟谁重复、听谁的,启用/新建/编辑后 toast 里提一句。**只提示不阻断**。
`PATH="$PATH:/x"` 这种引用自己的追加不算冲突——两段都往 PATH 里加东西是累积不是互斥;同一段内重复也不算。

### 5. Shell 轨的分组:字段,替换按类型分区(2026-09-11 实现)

- **为什么比方案更需要**:片段是全局的、只增不减,20～30 条很正常;原来按**类型**(变量 / alias / 脚本)分区是"长什么样"不是"干什么用",
  找 Java 相关的要在三个区各扫一遍
- **字段不做实体**:三问(组自己有属性吗 / 需要空组吗 / 被引用吗)全否,同方案。`ShellSnippet.group?: string`,
  `shell.json` 版本号不动(可选字段,旧文件直接能读)
- **分组 × 类型是两个正交维度,不是树**:Raycast 一级分区只能给一个——给分组;类型退成每行一个小图标。
  搜索栏的下拉位置被"项目轨 / Shell 轨"切换占了,所以**没有筛选下拉**,组名和类型名进 `keywords`,靠打字筛
- **组的先后 = 组内第一条片段在生成顺序里的位置**,未分组固定最后,桶内保持生成顺序。这样列表里 `#n` 大致递增,
  也不用为"组的顺序"另外存东西(方案那边组按字母排,因为方案没有顺序这个概念)
- **一个分组都没有时平铺、不摆标题**,类型分区不再出现——与方案页一致,避免"加了第一个分组分区就变样"之外再多一种模式
- **分组只管显示,不碰 `shell.sh` 生成顺序**。顺序真正要紧的场合少(`PATH` 追加先后、依赖前面的变量、同名覆盖听后者),靠 `#n` 手动调够用。
  将来若要"列表怎么排文件就怎么生成",用组内第一条的位置当组的位置、加"整组上移/下移";等排序真不顺手再说
- **整组启用 / 禁用**:之前否掉的"场景"的轻量版,不新增实体、不保存状态。全开着只显示「禁用整组」,全关着只显示「启用整组」,混着两个都显示;
  启用后跑重复设置检查。**整组改名 / 解散**同方案,但是全局的,没有"本项目"
- 生成文件的注释头带组名:`# [EXPORT] JAVA_HOME (Java) - 备注`,顺序不变
- 表单的分组控件(下拉 + 文本框)抽成 `useGroupFields`,方案与片段共用;分组类文案统一到 `grp.*`
- 顺手修的:片段历史的差异比对原先漏比 `containsSecret`,现在连 `group` 一起比

### 6. 全局搜索跟着调整(2026-09-11)

搜索的语义是"**现在哪里设了这个值**"。按这个语义对照新功能:

- **Shell 的重复设置在结果里标出来**:搜 `JAVA_HOME` 出两条都"已启用"的 Shell 行,看不出哪条生效;搜索恰恰是用户最容易发现"设了两处"的地方。
  被覆盖的那条打「被「片段 B」覆盖」灰标签,复用 `findShellConflicts`
- **Shell 来源带分组**:「Shell 轨 / Java / 片段名」,多一层定位,且来源参与匹配所以组名也能搜
- **方案进搜索,第三个分区排最后**:方案是变量值的正经存放处("客户老王的 API_KEY 是多少"答案在这),搜不到会被当成 bug,
  跟当初补 Shell 轨的理由一样。但它是候选值不是生效值,所以单独分区「方案里的」、来源写「项目 / 方案「名」」;
  原来的"匹配结果"分区改叫「环境文件里的」以示区分。同一个 key 出一行文件的 + N 行方案的不算噪音——能一眼看出各方案的值差在哪。
  跳过去落在项目页(方案没有文件);要精确落到那份方案上得给 `PresetsView` 加 `initialSelectedId`,以后再说
- **快照历史不进搜索**:历史是过去的状态,混进来会把"生效 / 候选 / 曾经"三层搅在一起。方案是候选不是历史,所以它能进而快照不能

### 7. 搜索拆成两个命令:`Search Env Vars` 管变量,`Jump to` 管"去某处"(2026-09-11)

上一节做完之后用户觉得搜索"有点混乱,想搜分组、搜方案该怎么办"。根因是**搜索的单位没理清**:
变量搜索一行是"一个 key 在某处的值",而"搜方案 / 搜分组"要的是"东西本身",目的是跳过去。两种单位塞一个列表就混了。

- **`Search Env Vars` 只管变量**,§6 的三处改动都留着。下一步给它加"来源"下拉(全部 / 环境文件 / Shell / 方案),未做
- **`Jump to` 只管跳转**,单位是项目 / 环境文件 / 方案 / Shell 片段,四个分区。回车 = 打开:项目页 / 停在该文件 /
  「管理方案」并选中 / Shell 轨并选中。方案页原先只能借道项目页打开(返回要退两级,验收时被指出),
  所以把"套用 = 写文件 + 记账"抽成 `applyPresetToFile`,`PresetsStandaloneView` 自己读 `.env` 后直接开方案页。
  次要动作:在 Finder 中显示、用其他应用打开、复制方案内容、**片段就地启停**(从启动器热插拔,唯一"不打开就能干活"的动作)
- **分组不是一行结果**,而是方案和片段的关键词——分组没有页面,跳到组员才有意义。类型词(export / alias / snippet,变量 / 别名 / 脚本)与 Shell 轨列表同一组
- 不搜:变量名和值(归 Search Env Vars)、快照历史、方案内容(内容里有密钥,且"内容里有 xxx"是变量搜索的语义)
- 否掉的:一个命令里用下拉切"搜什么"——每切一次列表结构和动作全变,比两个命令更绕;Raycast 惯例也是一种东西一个命令

### 8. 已开的终端拿的是老变量:提示与刷新(2026-09-11)

用户指出改了全局变量后已开的终端不会变,需要提醒并教怎么更新。此前只有恢复历史、启用集成的 toast 说"开一个新终端窗口即可生效",
最常用的启停 / 新建 / 编辑反而不说,不一致。

**前提先纠正**:"教他刷新"只能教一半。在已开终端里 `source ~/.env-butler/shell.sh` 能拿到**新增和修改**,
但**停用 / 删除**的东西它拿不掉——变量和 alias 已经在那个进程里,重新读文件不会 `unset`。文案必须把这半句说全。

做了三处,都很轻:
- 所有会重新生成 `shell.sh` 且改变生效内容的 toast 统一尾句"对新开的终端生效"(启停 / 新建 / 编辑 / 删除 / 排序 / 整组启停);
  改名 / 解散只改注释头,不带这句
- "Shell 集成"详情面板加「改完什么时候生效」:新终端自动;已开终端跑 source 拿到新增和修改;停用 / 删除要新开终端或手动 `unset` / `unalias`
- 「复制刷新命令」动作:每条片段的动作面板里有;"Shell 集成"那一项原有的「复制这一行」在已启用状态下改叫这个名字(同一行命令,两种身份)

不做:自动往已开终端里注入。Raycast 做不到,AppleScript 控制 Terminal / iTerm 太侵入。
