## 一、这是什么

**Env Keeper**(2026-09-11 由 Env Butler 改显示名,包名 / 数据目录 / 仓库名不变)—— 在 Raycast 里管理所有项目的 .env 文件和全局 shell 配置。本地、免费、键盘优先。

两个独立仓库(不是 monorepo,理由见设计决议 §七):

| 项目 | 路径 | 职责 | 包管理 | 分支 |
|---|---|---|---|---|
| core | `/Volumes/coding/project/env-butler`(包在 `core/` 子目录) | 纯逻辑,零 `@raycast/api` | **pnpm** | `main` |
| raycast | `/Volumes/coding/project/raycast-env-butler` | Raycast 扩展壳,只接界面 | **npm** | `main` |

docs(本目录)随 raycast 仓库管理。核心架构一句话:**.env 文件是真相源,core 不存环境数据,扩展直接编辑文件**——详见设计决议 §二。

两个仓库都已在 2026-09-05 完成首次提交(此前 2000+ 行代码没有任何版本历史)。

### 行内注释的解析规则(2026-09-06 落地,改动前务必先读)

`KEY=value # note` 的注释切分**刻意与 dotenv 保持一致**,不是自己定的规则:

- 值被引号包住时,先跳过整段引号,之后的第一个 `#` 才算注释
- 没有引号时,**第一个 `#` 就截断**(不要求前面有空格,所以 `SECRET=abc#123` 的值是 `abc`)

原因:值最终是被 Vite / Next 这类工具经 `dotenv` 读走的。规则不一致会导致
"界面显示的值 != 程序真正拿到的值",比不解析还危险。
已用 dotenv 17.4.2 写脚本逐例对照过 10 个用例,取值完全一致——
**以后要改这块解析,请重新跑一次对照,别凭感觉改。**

注释重排(统一成 ` # 正文`)只发生在**被编辑过的行**;没动过的行始终原样保留 `raw`,
所以不会出现"打开一下就把整个文件的空格重排了"。

## 三、Raycast 平台限制(逐条验证过,别再踩一遍)

这些都是实测 + 查官方类型定义/文档确认的,**不是推测**。遇到 UI 需求先看这张表:

| 想做的事 | 结论 | 依据 |
|---|---|---|
| 改表单 label / 输入框对齐、checkbox 视觉粗细 | **做不到**,原生控件样式固定 | 无样式接口 |
| `Form.Description` 设文字颜色 | **做不到**,只有 `title` / `text` 两个属性 | 类型定义 |
| 表单 `error` 提示换行显示到输入框下方 | **做不到**,固定显示在右侧、超长截断 + 悬停 | 类型注释 + 官网文档 + 实测 |
| markdown 正文里上色 | **做不到**,只支持 CommonMark | 官网文档 |
| markdown 表格(GFM table) | **不支持** | 官网文档 |
| ` ```diff ` 代码块自动上色 | **不会上色**(实测) | 实测 |
| Metadata 面板上色 | **可以**,`Label` 的 `text: {value, color}`、`TagList.Item` 的 `color` | 类型定义 |
| markdown + metadata 共存 | metadata **贴底固定**,markdown 内容短时中间留大片空白 | 类型注释 + 实测 |
| 自己写渲染组件 | **不行**。Raycast 用自定义 React reconciler 映射到 macOS 原生控件,没有 DOM / CSS / canvas;只能拼装官方组件 | grep 全量导出,无 `createElement` / `reconciler` / `canvas` |
| markdown 内嵌自绘图片(唯一"自由渲染"逃生口) | 技术可行(支持 `raycast-width` / `raycast-tint-color`),**但不建议**:不可选中/复制、宽度写死、需自己处理深浅色主题 | 官网文档 |
| Quick Look 预览 `.env` 文件 | **预览不了**。`.env` 无注册 UTI,系统给的是 `dyn.xxx`,类型链只有 `public.data`,不含 `public.plain-text` | `mdls` 实测 |
| 弹窗"取消"按钮、下拉框搜索框占位符 | 不显式指定就是**英文默认值**,必须传 `dismissAction.title` / `placeholder` | 已全项目修复 |

## 四、快照详情面板的设计拉锯(重要背景,别推翻重来)

这一块反复改了 5 轮,最终**回到彩色 emoji 方案**。演进与被否原因:

1. `🟢新增 / 🟡改动 + 箭头` 的项目符号列表 → 反馈"看都看不明白这个表达了什么"
2. 改成 ` ```diff ` 代码块的 `+` / `-` → 排版对、可读,但**没有颜色**
3. 改成 Metadata 面板(真彩色)→ markdown 与 metadata 共存产生**大片空白**
4. 去掉 markdown、内容也搬进 Metadata → **层次塌了**:分组标题和数据行长得一样、分隔线看不见、内容区左对齐与差异区右对齐割裂、diff 的 `-` / `+` 配对感被稀释
5. **回到 markdown + emoji(当前状态)**

**结论:在 Raycast markdown 里,彩色 emoji 是唯一能带颜色信号的手段。** Metadata 有真颜色但没有排版能力(无标题层级 / 分隔线 / 等宽块),代价过大。

当前保留的改进,后续改动**不要丢掉**:

- `###` 标题分组 + `---` 分隔线
- 敏感值统一打码(最早的 markdown 版把文件原样倒出,密钥明文可见,属于安全不一致)
- 快照内容区的注释行、空行原样保留

**一个待试想法**(尚未采纳):把颜色和 diff 惯例叠加,形如 `🟢 + FAKE_KEY=••••••••`,同时拿到颜色和方向性。如果再次收到"看不明白"的反馈,可以试这个。

## 五、开发环境

**每个仓库都装了提交前钩子**(`.githooks/pre-commit`,通过 `core.hooksPath` 生效),
提交时自动跑 `check`,不通过就中止。新克隆仓库后需要执行一次:

```bash
git config core.hooksPath .githooks
```

```bash
# core(改完必须 build,raycast 才读得到新逻辑 —— file: 是符号链接,不自动同步)
cd /Volumes/coding/project/env-butler/core
pnpm check        # typecheck + test + build,约 2 秒
pnpm test && pnpm build

# raycast
cd /Volumes/coding/project/raycast-env-butler
npm run check        # core check + typecheck + lint + test + build,约半分钟(提交前钩子跑的就是这条)
npm run dev          # ray develop,热更新
npm run build
npm run lint
npx ray lint --fix   # Prettier 报错时用这个,改完代码几乎每次都要跑
```

**踩过的坑**:

- ~~不要用 `tsc --noEmit`,它报的是假错误~~ —— **这条已作废(2026-09-06)**。
  那不是假错误,是 `tsconfig.json` 配错了两处:`moduleResolution` 缺省成 `node10`
  (不认识 `node:path` 这种前缀)、TypeScript 6 下 `types` 必须显式写出 `["node", "react"]`。
  两处补上后噪音全消,并暴露出 3 个一直存在的真类型错误。现在请用 `npm run typecheck`。
- 启动 `ray develop` 要用工具自带的后台方式,**不要在命令里手动加 `&`** —— 会导致进程编译完就退出,不进监听模式。
- `ray develop` 可能被系统按内存回收,看到 "killed / low memory" 不是代码问题,重启即可。

## 七、2026-09-06 那一大批改动

数据安全、两轨对齐、泄漏面、工程基建四组,逐条理由记在
`设计决议.md` §九,这里不重复。只强调三件动手前必须知道的:

1. **配置文件解析现在会抛错**。`parseRegistry` / `parseShellConfig`
   遇到坏 JSON 或版本过新会抛 `ConfigFileError`,不再返回空配置。
   `loadRegistry` / `loadShellConfig` 的返回值也变成了 `{ data, problem? }`。
2. **所有写文件都要走 `writeFileAtomic`**,别再直接 `writeFile`。
   它处理了符号链接和权限保留两个坑。
3. **`~/.env-butler/` 下多了两个目录**:`config-history/`(shell.json 与
   registry.json 的历史)、`backups/`(`.zshrc` 等 rc 文件的副本)。
   这三层历史是三件不同的东西,别搞混:`snapshots/` = 项目的 `.env`;
   `config-history/` = 扩展自己的 `shell.json`(片段);`backups/` = 用户自己那份 `.zshrc`。

## 七之二、2026-09-06 界面验收后的修正

第一次在真实 Raycast 界面里走查 §七 那批改动,发现的问题逐条记在
`设计决议.md` §十。动手前需要知道的:

1. **`List.Dropdown` 在挂载时会把当前选中项回调一次**。所以下拉里放"动作型"哨兵项时,
   必须保证首次渲染阶段它不是唯一可选项——否则一进页面就自己触发了。
   这次的表现是"进项目变成弹新建环境文件表单"。
2. **`diffEnvVariables` 的返回值多了 `baseDisabled` / `targetDisabled`**,
   且"值没变但被注释掉"现在算 `changed`。
3. **两个历史页的差异文案统一走 `views/diffFormat.ts`**,方向写死成 `A → B`,别再各写一套。
4. **`SnapshotCleanupForm` 已泛化**,不再绑定项目快照,新增 `navTitle` / `unit` / `onDelete` 三个入参。
5. **凡是按时间戳命名的文件,一律要过"同秒不撞名"这一关**。
   这次又栽了一回(`backupShellRc`),而且是端到端验证抓到的,读代码没看出来。
6. **片段历史的"恢复"动作会先算差异、点名连带影响的片段**(commit `fe4139f`)。
   在"某个片段的变更历史"里点恢复,恢复的仍是整份 Shell 配置——页面标题只提一个片段,
   动作却会把别的片段一起带回去。确认框现在会算一遍这一版跟当前配置的差异,
   把除本片段外还会被改动的片段逐个点名。同一提交也补齐了两处漏掉的
   "复制整行"(全局搜索结果项、项目轨已禁用区),且项目轨与 Shell 轨的"禁用"
   语义不同:前者是整行被注释、复制要带 `#`,后者是片段不生成、行本身没被注释。
