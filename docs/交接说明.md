## 一、这是什么

**Env Butler** —— 在 Raycast 里管理所有项目的 .env 文件和全局 shell 配置。本地、免费、键盘优先。两个包:

| 项目 | 路径 | 职责 | 包管理 |
|---|---|---|---|
| core | `/Volumes/coding/project/env-butler/core` | 纯逻辑(.env 解析等),零 @raycast/api | **pnpm** |
| raycast | `/Volumes/coding/project/raycast-env-butler` | Raycast 扩展壳,只接界面 | **npm** |

docs(本目录)随 raycast 项目管理。核心架构一句话:**.env 文件是真相源,core 不存环境数据,扩展直编文件**——详见设计决议 §2。

## 四、常用命令

```bash

cd /Volumes/coding/project/env-butler/core
pnpm test          # vitest 跑测试
pnpm typecheck     # tsc 类型检查
pnpm build         # 产出 dist/(raycast import 的目标)

# raycast
cd /Volumes/coding/project/raycast-env-butler
npm run dev        # Raycast 里热更新(需 Raycast 打开)
npm run build      # 构建验证
```

## 六、关键纪律(别破坏)

- **core 零平台依赖**:禁止 import `@raycast/api`、`@tauri-apps/*`;保持纯函数,副作用(时间等)走参数注入——方便测试、未来换平台(设计决议 §6)
- **core 用 pnpm,raycast 用 npm**:商店 CI 只认 npm 的 lockfile(设计决议 §7)
- **core 改动要 pnpm build**:file: 是符号链接,不 build 的话 raycast 读到的是旧 dist
- **docs 在 raycast 项目里**:设计文档和代码一起走,改决议记得同步改这里
