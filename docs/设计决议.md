## 一、产品定位

**在 Raycast 里管理所有项目的 .env 和全局 shell 配置——本地、免费、键盘优先。**

- 形态:Raycast 扩展(TS + React)
- 策略:先自用再上架,按上架标准写代码(数据结构、错误处理不糊弄)
- 更新:上架后由 Raycast Store 自动推送(npm run publish,版本号 package.json,说明写 CHANGELOG.md)

## 二、核心架构(最关键的三刀)

### 1. 真相源 = .env 文件本身(不是扩展数据库)

- 扩展**不存环境数据**。项目轨就是直接编辑项目目录下的 .env 文件
- 私有存储只存:项目注册表、UI 状态、快照历史、"上次读取的文件指纹"
- **冲突检测**(Q2c+Q6c 的落地):打开项目时读文件并记指纹 → 保存时再摸一次文件:
  - 指纹一致 → 直接写入
  - 指纹变了(外部改过)→ 弹窗:载入新版 / 强行覆盖
- 不做自动双向同步、不做后台文件监听(v1)

### 2. 双轨文件模型

| 轨 | 真相源 | 生效方式 |
|---|---|---|
| 项目轨 | 项目目录下 `.env.<环境名>` | 前端框架/Docker 原生读取;可选 direnv 转发(v2) |
| shell 轨 | 扩展拥有的 `~/.env-butler/shell.sh` | `.zshrc` 一行 source;该文件用户不该手改 |

- 项目轨:扩展改的就是项目那个 .env 文件,没有第二份
- shell 轨:两个文件(.zshrc 只有一行 source,内容在 shell.sh);alias 不做独立概念,就是片段

### 3. 扩展私有存储 = 自建目录,全透明

```
~/.env-butler/
  ├── registry.json         ← 项目注册表(项目名、路径、敏感标记)
  ├── shell.sh              ← shell 轨生成文件
  └── snapshots/
      └── <项目名>/
          └── 2026-09-01-183430.env.development
```

- 不用 Raycast localStorage 存业务数据(叙事一致性:本地、透明、用户拥有;换机 = 拷目录)

## 三、v1 功能范围

### 项目轨
- [ ] 项目注册:手动添加 + 按最近使用排序(Q8)
- [ ] 变量 CRUD:List 列表 + ⌘E 进 Form 编辑(单行值/多行值/行内注释分开处理)(Q17)
- [ ] 启用/禁用 = 注释/取消注释该行(dotenv 惯例)(Q16)
- [ ] 敏感字段自动识别:命名含 KEY/TOKEN/SECRET/PASSWORD/PASSWD/CREDENTIAL(大小写不敏感)→ 列表打码、编辑表单明文;可手动标记/取消;标记存在 registry.json,**不写入 .env**(Q7+Q18)
- [ ] 多环境:任意命名(不硬编码 dev/prod),一环境一文件 `.env.<名字>`;不做全局切换;提供"复制某环境为 .env"动作(Q5)
- [ ] 快照:每次写入前备份到 snapshots/,免费回滚;每项目 500 份软上限(超限提示,不自动删)(Q10+Q12)
- [ ] `.env.example` 一键生成/更新:键保留、值清空占位(Q13)
- [ ] dotenvx 感知:识别 `encrypted:` 前缀,显示占位、编辑时禁止破坏(Q14b)
- [ ] .envrc:检测到时仅提示、绝不改动(Q14c)

### shell 轨
- [ ] 片段 CRUD + 启用/禁用(生成文件时剔除禁用项)(Q9b)
- [ ] 生成 `~/.env-butler/shell.sh` + 首次引导写入 .zshrc 一行 source
- [ ] alias = 片段的一种预设,无独立模块

### 全局
- [ ] 命令结构(共 2 个入口)(Q11):①主命令(项目/轨道管理) ②全局搜索变量(跨项目搜 KEY)
- [ ] 保存校验(差异化):shell 片段 `zsh -n`;.env 做 KEY=value 格式校验;附生效范围提示("对新开终端生效")

## 四、明确不做(v1 砍掉)

仪表盘/图表 · 主题切换 · 账号/会员 · 自建更新机制 · 全局激活项目概念 · 自动双向同步 · direnv 完整集成(v2) · 加密/密钥管理(v2,与 dotenvx 互补) · PATH 通过 launchctl 注入宣传(系统限制,不可承诺)

## 五、差异化卖点(商店页面三行)

1. **Secrets masked by default** — 敏感值默认打码,一键揭示/复制
2. **Snapshot & rollback, free forever** — 每次修改前自动快照,.env 不进 git 也有历史
3. **One-click .env.example** — 从任意环境生成团队模板

## 六、核心分层与跨平台复用（2026-09-01 补）

**动机**：不把功能绑死在 Raycast。若弃用 Raycast，丢的只是 UI 壳，核心逻辑与数据零损失；核心也可复用到将来的个人工作台 / CLI。

### 分层原则

```
raycast/（壳,只接界面） → 依赖 → core/（纯逻辑,零平台依赖）
```

- **core**：纯 TypeScript + Node,不出现任何 `@raycast/api` / `@tauri-apps/*` 引用。全部是"领域操作"(解析 .env、生成 .sh、快照命名、冲突指纹、脱敏识别)。
- **raycast(壳)**：只 import core,用 List/Form/Detail 把核心操作映射成界面,**不写业务逻辑**。

### 朴素分层(现在只用到的两条,不提前做接口)

Node-only 阶段(现消费方全是 Node:Raycast/CLI/未来的 Electron)**不做接口抽象**,只有两条纪律:

1. **数据变换写成纯函数**:输入字符串 → 输出结构/字符串,不碰 fs。如 `parseEnv(input): EnvEntry[]`、`generateSh(entries): string`。测试直接喂字符串断言。
2. **一次性副作用靠传参注入**:如快照命名的时间戳 `snapshotName(t: Date)`,默认传 `new Date()`,测试传假时间。fs / child_process 在 Node-only 下直接用,不抽象。

### 端口预留(仅当出现第二个非 Node 消费方时才落地)

| 端口 | 各平台实现 |
|---|---|
| EnvStore(读写 .env) | Node:`node:fs` / Tauri:`@tauri-apps/plugin-fs` / Web:无(砍掉形态的原因) |
| Exec(执行 shell) | Raycast:`useExec` / Node:`child_process` |
| Time(时间戳) | 各平台 Date |
| Secrets(可选密钥存储) | Raycast 加密库 / 工作台自己的存储 |

> 跨语言说明:接口契约能被重写成任何语言(20 行),真正的资产是 core 里的纯算法;跨语言时用 WASM/FFI 或重写,接口形状作文档约定保留。

### core 纪律(用 ESLint 强制)

- `no-restricted-imports`:禁止 `/Volumes/coding/project/env-butler/core` 目录 import `@raycast/api`、`@tauri-apps/*`
- core 只暴露领域操作,不暴露 `showToast()`、`getPreferenceValues()` 等平台 API
- core 每个 src 文件保持**纯函数 + 显式副作用参数**,便于 vitest 直接断言(见 §六"朴素分层")

## 七、仓库结构(实际:两独立项目平级,非单仓库)

> 2026-09-02 修订:放弃"单仓库 + packages/ + docs 并入"的设想。接受实际布局——core 与 raycast 是**两个平级的独立项目**,各自有自己的包管理,彼此用 npm file: 依赖联结。

### 实际布局

```
/Volumes/coding/project/
├── env-butler/                    ← @env-butler/core(纯逻辑,PNPM 管理)
│   ├── package.json               ← name: @env-butler/core,exports → dist
│   ├── tsconfig.json              ← typecheck/编辑器(含测试,noEmit)
│   ├── tsconfig.build.json        ← build(排除 *.test.ts)
│   ├── src/{index,parseEnv}.ts + parseEnv.test.ts
│   └── dist/                      ← pnpm build 产物(raycast import 的目标)
└── raycast-env-butler/            ← Raycast 扩展(壳,NPM 管理)
    ├── package.json               ← name: raycast-env-butler;依赖 @env-butler/core
    ├── package-lock.json          ← npm 生成,提交商店用
    ├── docs/                      ← 本文档 + 功能整理 + 竞品分析(随扩展提交)
    └── src/manage-envs.tsx
```

docs(功能整理 / 竞品分析 / 设计决议)已移入 raycast 项目的 docs/,随扩展一并管理。

### 包命名

- 扩展项目(npm name):`raycast-env-butler`(Create Extension 时确定)
- 核心包(npm name):`@env-butler/core`(已发布语义的本地包)
- "env-butler" 仅作产品/仓库根的概念名,不是任何实际包名

### 核心约束：raycast 必须独立于 pnpm(2026-09-01 修订,推翻此前 workspace 方案)

**喂给商店的是整个源码项目**(PR 进 raycast/extensions 仓库),商店 CI 用 **npm** 跑 `npm install`,官方要求提交 `package-lock.json` 以锁定确切版本(保证"本地装的版本 == 商店装的版本")。**商店只认 npm 的 lockfile,不认 pnpm/yarn 的;也不认 workspace: 协议。** 因此正解是：

- ✅ raycast/ 自成一体:自己的 package.json + package-lock.json,本地就用 npm 操作这个包,pnpm 不碰它(锁文件由 npm 生成,交商店才"安装一致")
- ✅ core 作为**已发布的真实版本依赖**进 raycast:`"@env-butler/core": "^0.0.1"`(本地开发期用 file:,提交前换版本号)
- ✅ core 自己用 pnpm 没问题(core 是发往 npm 的对象)
- ❌ 反例(pnpm workspace 一把梭)行不通:商店 CI 的 npm 不认识 workspace 协议;根目录 pnpm-lock.yaml 商店也不读,版本不受控

### 开发与发布循环(2026-09-02 实测修正)

```
日常开发:  raycast 目录内 npm run dev(热更新);core 单独用 pnpm test
联动 core: 本地 file: 依赖是符号链接 → core 源码改动不会自动生效,
           必须先在 core 目录跑 pnpm build(tsc 出 dist),raycast 才读到新逻辑
发布:      npm publish core → 把 raycast 的依赖从 file: 改成 ^版本号 + npm install 刷新 lockfile
           → npm run publish 提商店
```

- **单人推荐**:日常在 core 改完就 `pnpm build`,raycast 立即经符号链接读到;提交商店前写一个 5 行脚本把 `file:../env-butler/core` 换回 `^版本号` 并 `npm install`(只有一处替换,可靠);同时保持 core 小步发版(0.x 随便升)做双保险
