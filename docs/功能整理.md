## 一、核心数据模型

- **作用域双轨**：通用配置（真全局项）/ 项目配置（按项目隔离）。原版两轨"二选一竞争生效"；扩展新方案 = 通用常开、项目变量随目录生效（见第五节）。
- **分组**：属于某个项目/通用配置之下，可关联多个变量（分组名称 15 字上限、分组备注 150 字上限）。
- **变量**：核心单元 = **备注（身份）** + **内容** + **启用状态**。通用配置内容为 shell 片段（任意多行 export/alias）；项目配置内容为 KEY=value（.env / dotenv 格式）。
- **多环境**：一个变量可存多套值（开发/测试/生产）。原版为"应用内一键切换"；扩展方案 = 每环境生成一份 .env.<名称> 文件，框架按 NODE_ENV 自动取用（见第五节）。
- **快照**：按“作用域 + 版本号”存 JSON（如 `common/common-v1.json`），可查看、可回滚。

## 二、功能清单（按模块）

- 抽屉式面板
- 新增分组（名称必填 / 关联变量多选 / 备注）

### 6. 操作记录 / 快照
- 按作用域筛选（通用配置 / 项目）
- 「全部 / 可恢复」过滤
- 表格：时间 / 备注 / 快照路径 / 版本号
- 查看快照、回滚到历史版本（原版为会员能力）
- 快照上限可配置（默认 30，建议 30–200，超限自动清理最旧）

### 7. 设置
- 快照上限配置（默认 30，建议 30–200）
- 软件更新（自动下载 / 检测更新 / 立即升级）
- 主题切换（Light / Dark / Black / 跟随系统）
- 账号体系（游客模式 / 登录注册；原版有会员）

## 四、Raycast 扩展的 UI 能力边界（UI 重设计的画布）

| 组件 | 用途 |
|---|---|
| List（主力视图） | 搜索框 + 分组（Section）+ 行（图标/标题/副标题/右侧标签），行内可放开关——变量列表 |
| Form | 输入框 / 多行文本 / 下拉 / 复选 / 文件选择——新增/编辑变量表单 |
| Detail | Markdown 面板，支持代码块——实时预览最终生成的 .sh |
| ActionPanel | ⌘K 动作菜单——删除/复制/回滚/切换环境等二级操作 |
| Toast / ConfirmAlert | 操作反馈与危险操作确认 |
| MenuBarExtra（可选） | 菜单栏常驻快速入口；原设想的"当前生效环境/作用域"状态展示已随全局激活概念一起取消 |
| Grid | 图标卡片（大概率用不上） |

做不到：任意自由布局、图表、自定义字体/配色（跟随 Raycast 主题）、拖拽排序（用动作菜单的上移/下移代替）、自定义浮窗。
交互哲学：键盘优先 = 搜索 + 回车 + 快捷键；窗口约 800px 宽的中央面板，不是独立窗口。

> 结论：能重新设计的是信息架构与操作流，不是像素——视觉由 Raycast 统一，比原版模板风更统一耐看。

## 五、形态与范围决议（2026-09-01）

- ❌ 砍掉：仪表盘/统计图、主题切换、账号/会员、软件更新模块
  - 更新机制：上架 Raycast Store 后由 Raycast 自动推送更新（`npm run publish` 提交，版本号在 package.json，发布说明写 CHANGELOG.md），无需自建更新逻辑
- ❌ UI 不抄原版截图，按 Raycast 组件重新设计信息架构
- ✅ 导入/导出：做
- ✅ 实时预览：做（Detail 面板渲染最终生成的 .sh，顺带解决原版"片段顺序不可见"的问题）
- ✅ alias：不单独做模块，作为 shell 片段的一种类型/新建预设（本质与变量相同）
- ✅ 项目配置生效模型（2026-09-01 修订，推翻原「通用常开+项目叠加」方案）：
  - 原版「全局激活项目」模型有致命缺陷——项目变量污染全局所有终端/进程；无法并行开发多个项目；切换后已开终端环境不一致
  - 新方案：通用配置（真全局项）→ .zshrc 一行 source；项目配置 → 写入【项目目录下的 .env 文件】（.env.development / .env.production，前端框架原生读取，天然并行、不污染全局）；砍掉「全局激活项目」概念
  - 可选 direnv 集成：生成 .envrc 覆盖「终端 CLI 需要项目变量」场景（每个终端按所在目录取环境）
  - 扩展定位 = 所有项目 env 的中央管理台：注册项目绑定目录、集中管理变量与多环境、生成/同步 .env、预览、快照、导入导出

### 原版的三大软肋（= 扩展的差异化机会）
1. **恢复快照收费** → 扩展免费
2. **无语法校验 + 无生效范围提示** → 扩展保存时 `zsh -n` 校验 + "对新开终端生效，GUI 应用需重启"提示
3. **GUI 应用读不到环境（只写 .zshrc）** → 可选补 `launchctl setenv` 层

## 六、MVP 范围

- [ ] 变量：增删改查 + 启用/禁用开关（通用/项目两轨共用）
- [ ] 通用配置：真全局项（JAVA_HOME、代理等）→ .zshrc 一行 source
- [ ] 项目：增删改查 + 绑定项目目录；项目变量 → 生成项目目录下的 .env 文件（.env.development / .env.production，框架原生读取）；不设「全局激活项目」
- [ ] 分组：创建 + 关联变量 + 筛选
- [ ] 多环境：每个环境生成一份 .env.<名称>（.env.development / .env.production…），框架按 NODE_ENV 自动取用；不做原版"全局一键切换"（与并行开发冲突）；提供"复制某环境为 .env"动作备用
- [ ] alias：作为通用配置的新建预设（shell 轨专属；.env 格式没有 alias 概念），不做独立模块
- [ ] 实时预览：Detail 面板渲染生成产物——通用的 .sh 与项目的各 .env.<名称>（顺带解决原版"片段顺序不可见"问题）
- [ ] 快照：自动记录 + 免费回滚（差异化点）
- [ ] 保存时校验（差异化点）：通用 shell 片段用 zsh -n；项目 .env 做 KEY=value 格式校验；附生效范围提示
- [ ] 导入 / 导出：JSON 配置文件备份与迁移
- [ ] （可选）`launchctl setenv` 层覆盖 GUI 应用（差异化点）
